# Whale Lab reliability audit — 19 September 2026

## Findings fixed in this pass

- 130 of 214 WATCH wallets in the inspected 1,340-wallet snapshot had nonpositive lifetime position PnL. WATCH appeared under Worth following. Non-profitable rankable wallets now receive NOT COPYABLE; the browser also corrects old snapshot verdicts while waiting for the next pipeline refresh.
- Successful position requests used to remain authoritative indefinitely after failures. Failed checks and observations older than six minutes now show unavailable/old data, suppressing current-price PnL and exit alerts. The six-minute threshold is a conservative display policy, not a guarantee of upstream freshness.
- Five-second REST polling was advertised as seconds-latency tracking despite the documented five-minute CDN cache. The interface now discloses this delay. Requests have timeouts, HTTP/schema checks, a four-worker concurrency limit, and no overlapping batches.
- A closed position from before a copy was saved could trigger a new exit alert. Such a record no longer confirms that this copy's whale has subsequently exited.
- Legacy copies could recover the wrong condition ID from repeated titles or empty slugs. Migration now requires a nonempty matching slug and one unique condition; unresolved legacy copies remain unknown.
- API outcome/title/name strings interpolated into HTML are escaped. Notification support is checked without referencing an undefined global. Invalid saved copy records and impossible entry/stake values are rejected.
- 114 of 295 closed-position rows had zero cost. Normalization now falls back to total_size × avg_price, as documented by the API client. This updates newly generated snapshots; no historical data was fabricated.
- A disconnected websocket immediately stops displaying Live while reconnecting.
- Profit/drawdown is no longer labelled profit per dollar risked. Daily-sampled drawdown is explicitly distinguished from intraday account risk, and paper PnL is labelled before fees/slippage.
- Added dependency-free regression tests and a separate GitHub Actions check workflow.

## Remaining work, in priority order

1. **Reliable collection and outage visibility.** Configure the already-identified external workflow pinger using a securely held Actions-write credential. Add per-source success counts, last-success times, and capped/truncated coverage metadata. A failed request must not appear as an empty successful dataset. Preserve last-known good snapshots on partial outages. The current pipeline's low absolute wallet-count floor can still publish substantial partial data loss.
2. **Exact position coverage.** The board only includes up to 12 open and 8 closed positions per screened wallet. API checks remain dependent on the visitor reaching Polymarket. Verify pagination for exact-market lookups, expose coverage, and use an authorized deployed relay when direct requests fail. Closed positions should be selected by recent event time rather than relying on the default value ordering. Test close/reopen cycles and partial reductions separately from full exits.
3. **Publish consistency and socket health.** Add build IDs across all JSON files; reject mixed builds in the browser. Refresh scorecards in long-lived tabs. Detect a connected socket that stops delivering activity, and implement/test relay-to-direct failover. Review refresh.yml's `git rebase -X ours`: in a rebase, ours is the upstream side, contrary to the comment about preserving newly generated output.
4. **Actual trade journal.** Record the user's executed entry, quantity, commissions, slippage, stop, target, time, exit and reason. Current My Copies assumes the displayed whale/market price; its PnL is an estimate and is not broker reconciliation. Add export/import and schema migrations before relying on browser-only storage.
5. **Firm-specific risk monitor.** First collect firm, product, phase, account size, allowed instruments, reset timezone, daily-loss formula, static/trailing drawdown rules, consistency rules, news/overnight restrictions and commission treatment. Store a dated official rule source. Calculate remaining headroom from actual equity including open PnL and costs, and aggregate stop risk across correlated trades. A static notebook cannot enforce broker-side limits or protect an account while the tab is closed.
6. **Forward validation.** Save signals and the wallet cohort as they existed at decision time. Evaluate future trades without selecting today's winners retrospectively. Include missed fills, realistic delays, spread, fees and slippage. Report sample size, expectancy in R, losing streaks, daily/intraday drawdowns and rule breaches. Test on the actual instrument traded; a Polymarket outcome is not a futures/FX/CFD entry signal.
7. **Scoring semantics.** Curve timestamps measure observation recency, not last trade activity; days_idle can therefore mislabel activity. Lifetime fills divided by available curve observations can overstate trading frequency if history is truncated. Monthly consistency includes the current partial month and does not explicitly account for missing months. Profit/drawdown lacks starting equity and cannot establish account-percentage drawdown or prop-firm suitability.

## Suggested product direction

Make Whale Lab a research input to a decision journal and risk monitor. For each proposed trade, record the independent thesis, relevant whale observation and its age, instrument mapping, invalidation, stop-based size, account headroom and subsequent outcome. Avoid treating a whale rank, stablecoin transfer or event probability as sufficient evidence to enter a different market.

Firm rules must be selected explicitly. For example, FTMO's official objectives distinguish account products and define limits using equity; one generic “5% daily / 10% total” preset is not adequate for all programs. Official reference: https://ftmo.com/en/trading-objectives/ . No firm-specific preset was implemented without knowing the intended account.

## Validation

Run `node --test tests/tracking.test.cjs` and `python -m unittest discover -s tests -p 'test_*.py'` from the repository root. Browser smoke testing covers the scored board and My Copies delay disclosure. This is a targeted reliability pass, not a certification of strategy profitability, complete API correctness, or prop-firm compliance.
